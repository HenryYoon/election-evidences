# 0002 검색·AI 도달

- 작성자: 윤희승
- 상태: 승인됨 (2026-10-10)
- 다음 단계: `spec/0002-search-reach.md`
- 앞 문서: `intent/0001-evidence-desk.md`

## 문제
- 0001은 회수 기반을 갖췄다. 경로마다 HTML에 제목, 설명, H1, 첫 문단이 있고, 사이트맵과 robots.txt가 있다.
- 0001의 검사는 합성 데이터로 만든 빌드 결과물만 본다. 실제 배포 사이트의 성능, 리다이렉트, 실제 데이터로 만든 페이지는 아무도 점검하지 않는다.
- AI 에이전트와 생성형 검색은 페이지를 한 번 요청하고, 태그를 벗기고, 토큰 예산 안에서만 읽는다. 홈과 기록 목록 HTML은 138KB, 119KB다. 그중 본문은 5% 안팎이고 나머지는 데이터 스냅샷과 지도 경계선이다.
- 사이트 전체를 한 번에 파악할 색인(`llms.txt`)과 기록별 마크다운이 없다.
- 기준점: agentic-seo 0.x 감사 결과 F 37/100 (2026-10-10, 로컬 빌드).

## 기대 결과
- 검색엔진과 AI 에이전트가 적은 토큰으로 사이트 전체와 기록 하나하나를 읽는다.
- 실제 배포 사이트를 주기적으로 점검하고, 점수가 떨어지면 드러난다.
- 실제 도달은 Search Console 노출, 클릭, 색인 수로 본다. 점검 점수는 방향 지표다.

## 영향 받는 사용자와 시스템
- 독자: 검색과 AI 답변을 거쳐 오는 시민과 기자.
- 운영자: 점검 결과를 GitHub Actions에서 본다.
- 시스템: `scripts/prerender.mjs`, 공개 페이지, GitHub Actions.

## 제약
- 점수를 올리려고 사이트와 맞지 않는 파일을 두지 않는다. `skill.md`, `agent-permissions.json`, 사이트용 `AGENTS.md`는 호출할 API나 개발 문서가 있을 때 쓰는 신호다. 이 사이트에는 없다.
- 키워드를 반복하지 않는다(0001 명세 6장).
- 개인정보 규칙은 새 출력물(`llms.txt`, 마크다운)에도 그대로 적용한다.
- 외부 점검 도구(Lighthouse CI, agentic-seo)는 CI에서만 돌린다. 운영자가 실행을 허용했다(2026-10-10).

## 열린 질문
- Search Console API 자동 수집: OAuth 설정이 필요하다. 등록 뒤 운영자가 월 1회 직접 본다.
- AI 트래픽 측정: Vercel 로그의 사용자 에이전트를 MCP로 읽을 수 없다. 나중에 정한다.
