# 0001 선거 증거 데스크

- 작성자: 윤희승
- 상태: 승인됨 (2026-10-08)
- 다음 단계: `spec/0001-evidence-desk.md`

## 문제
- 현재 사이트는 지도 한 화면에 증거 카드를 모아 둔 단일 페이지다.
- 증거 카드, 외부 발신 소식, 시민 제보, 통계가 들어갈 자리가 구분되어 있지 않다. 이 기록들을 한 화면에 섞으면 독자가 건수를 합쳐서 읽는다.
- 빌드 결과 HTML이 비어 있다. 검색엔진과 생성형 검색은 페이지 문단을 회수해서 인용한다. 빈 HTML은 회수할 문단이 없다.

## 기대 결과
- 한 도메인 안에 네 층(기록, 피드, 제보, 통계)을 분리해 둔다.
- 층마다 기록의 성격이 다르다는 점을 화면이 드러낸다. 층끼리 건수를 합치지 않는다.
- 경로마다 빌드 결과 HTML에 제목, 설명, H1, 첫 문단이 들어 있다.
- 상태는 조사 분류이며 법적 결론이 아니라는 문장을 홈, 기록, 통계 첫 화면에 고정한다.

## 영향 받는 사용자와 시스템
- 독자: 증거 카드를 검색이나 링크로 찾아오는 시민과 기자.
- 제보자: 새 공개 제보 폼으로 제보를 보내는 시민.
- 운영자: `/admin`에서 기록, 피드, 제보, 통계를 관리하는 사람.
- 시스템: Vite + React 프론트엔드, Supabase(Postgres, Storage), Vercel 배포, `scripts/`의 Python ETL.

## 제약
- 도메인은 하나다. 같은 콘텐츠를 복제한 미러 사이트를 만들지 않는다.
- 제보자 이름과 연락처는 공개면에 올리지 않는다.
- 의혹을 확인 상태로 자동으로 올리지 않는다.
- 운영자는 한 명이다. 운영 부담이 큰 구조는 피한다.

## 열린 질문
- 상태 필드를 유지할지: 운영자는 필요성에 의문을 제기했다. 플랜은 통계 모수 정의에 필요하다는 이유로 유지를 제안했다. 운영 중 다시 판단한다.
- 피드 수집 범위: 유튜브는 채널 RSS로 수집한다. X 등 다른 SNS는 미정이다.
- 통계 1편에 쓸 공식 표: 운영자가 나중에 제공한다.
