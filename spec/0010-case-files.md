# 0010 정리 페이지 — 명세

- 의도: `intent/0010-case-files.md`

## 1. 주소
| 주소 | 내용 |
|---|---|
| `/cases` | 정리 글 목록. 제목, 한 줄 요약, 연결 증거 수 |
| `/cases/<slug>` | 정리 글 하나 |

- 상단 내비게이션의 첫 자리에 "정리"를 둔다. 보이는 정리 글이 하나도 없으면 링크와 `/cases`를 만들지 않는다.

## 2. 저장
- `src/content/cases.ts`에 구조화한 데이터로 둔다. 관리자 화면은 만들지 않는다. 변경 이력은 git에 남는다.
- 필드: `slug`, `title`, `summary`(H1 뒤 첫 문단이자 description, 150자 이하), `state`(`draft` | `published`), `updated`, `records`(연결 증거 id), `sections`(소제목과 문단. 문단마다 근거 증거 id), `unconfirmed`(확인하지 못한 것), `excluded`(옮기지 않은 내용과 이유).
- 문단의 근거 id는 `records`에 있어야 한다(단위 테스트).

## 3. 페이지 구성
1. H1 제목, 첫 문단 요약.
2. 검증 상태 상자: 연결 증거 수와 상태별 수를 데이터에서 계산한다. 문서 확인·영상 확인이 0건이면 "운영진이 확인한 내용은 아직 없다. 아래는 제보 내용을 정리한 것이다"를 표시한다.
3. 본문: 소제목별 문단. 문단 끝에 근거 증거 번호를 링크로 단다.
4. 확인하지 못한 것.
5. 옮기지 않은 내용.
6. 연결된 증거 목록(증거 목록과 같은 행 모양).
7. 면책 문장과 정정 요청 링크(`/contact`).

- 데이터에 없는 증거 id(비공개로 바뀐 기록 등)는 링크와 목록에서 뺀다.

## 4. 초안과 공개
- `draft`는 운영 빌드에 나오지 않는다. 빌드 환경 `VERCEL_ENV=preview`(Vercel PR 미리보기) 또는 `CASE_DRAFTS=1`(CI·로컬)일 때만 나온다.
- 초안 페이지에는 `noindex`를 달고, 사이트맵과 llms.txt에 넣지 않는다. 화면 위에 "승인 전 초안"을 표시한다.
- 운영자가 미리보기에서 읽고 승인하면 `state`를 `published`로 바꿔 머지한다.

## 5. 회수
- 공개 글은 사이트맵, llms.txt에 들어간다. title, description, canonical, H1 하나, 첫 문단 규칙을 지킨다.
