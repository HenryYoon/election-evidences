# 0001 선거 증거 데스크 — 명세

- 원본: `spec/0001-evidence-desk-handoff.pdf` (빌드 핸드오프, 2026-10-08)
- 의도: `intent/0001-evidence-desk.md`
- 이 문서는 원본 PDF의 텍스트판이다. 원본과 이 문서가 다르면 원본이 우선한다.
- 운영자 결정(2026-10-10): 원본의 층 이름 "원장"과 주소 `/ledger`를 이 문서와 구현에서는 "기록"과 `/records`로 쓴다. 이 결정은 원본보다 우선한다.
- PDF 속 그림의 영어 라벨, 지명, 수치는 자리표시다. 집계 결과가 아니다.

## 1. 층
| 층 | 내용 | 규칙 |
|---|---|---|
| 기록 | 사진, 영상, 문서가 있고 날짜, 장소, 상태, 출처가 붙은 증거 카드 | |
| 피드 | 올공, 자혁 등 발신 소식 | 증거로 승격하지 않는다. 카드가 되면 기록 주소만 링크한다 |
| 제보 | 시민 제보(휴민트) | 기본 상태는 미확인. 인명과 연락처는 공개면에 올리지 않는다 |
| 통계 | 기록과 공식 표를 계산한 결과 | 지도는 질문 하나에 한 장 |

- 층은 서로 다른 기록이다. 층끼리 건수를 합치지 않는다.
- "상태는 조사 분류다. 법적 결론이 아니다." 이 문장을 홈, 기록, 통계 첫 화면에 고정한다.

## 2. 하지 않는 것
- 같은 콘텐츠의 도메인 분양, 선거명만 바꾼 미러.
- 홈에 층별 건수를 큰 숫자로 노출. 숫자는 통계 표 안에만 둔다.
- 피드, 제보, 좌표 없는 카드를 통계 지도에 찍기.
- 피드와 제보를 기록 건수나 통계 모수에 합산.
- Google Analytics를 노출 수단으로 먼저 설치. 색인은 Search Console과 사이트맵이 맡는다.
- `user-scalable=no` 유지. 제거한다.
- 한 페이지에 H1 여러 개. 페이지당 H1은 하나다.

## 4. 데이터
- 공통 필드: `id`, `layer`, `updatedAt`.
- 상태 정의는 코드 상수와 페이지 범례가 같다.
- 의혹을 확인으로 올리는 기본값은 없다.

### 기록 Evidence
- `status`: `document`, `video_confirmed`, `reported`, `allegation`
- `occurredAt`, `placeName`, `lat`, `lng`. 좌표는 없을 수 있다.
- `claim`(한 문장), `election`, `type`
- `sources`: `title`, `url`, 선택 `archiveUrl`
- `verification`: 보인 것, 장소, 시각, 주장하지 않는 것. 각 한 줄.

### 피드 FeedItem
- `source`, `sentAt`, `text`, `url`
- `evidenceId`는 기록으로 승격된 경우에만 둔다.

### 제보 Tip
- `status` 기본값 `unverified`. `placeName`, `sentAt`, `heard` 한 줄, `notClaimed` 한 줄.
- 공개 필드에 이름, 전화, 계정을 넣지 않는다.

### 통계 Analysis
- `period`, `universe`, `method` 네 줄, `sourceTable`, `includedEvidenceIds`
- `excluded`: 피드, 미확인 제보, 좌표 없는 카드, 주장만 있는 카드
- `geo`: `choropleth` 또는 `dots` 중 하나. 한 분석에 둘을 겹치지 않는다.
- `rows`: 구역 또는 장소, 값, 단위

## 5. 화면

### 홈 `/`
- 홈은 입구다. 콘텐츠를 펼치지 않는다.
- 상단 한 문장에는 건수를 넣지 않는다. 예: "2026-06-03 서울 기록. 상태는 조사 분류이며 법적 결론이 아니다."
- 왼쪽은 지도, 오른쪽은 오늘 기록 세 줄이다. 각 줄은 시각, 장소, 상태, 한 줄, 출처다.
- 아래 네 카드는 기록, 통계, 피드, 제보다. 카드 안은 제목, 최신 한 건의 신원, 링크다.
- 홈에서 피드를 발신처별로 나누지 않는다.
- 모바일은 같은 순서를 세로로 쌓되 숫자 대신 최신 한 건을 쓴다.

### 기록 `/records`, `/e/:id`
- 목록 행: 사진 칸, 시각, 장소, 상태, 한 줄, 출처.
- 필터: 유형, 선거, 상태, 지역.
- 상단 집계 숫자는 구현에서 빼거나 필터 결과 보조로만 둔다.
- 상세 첫 문장에 날짜, 장소, 상태, 출처가 들어간다.
- 상세 왼쪽은 매체와 아카이브 시각, 오른쪽은 상태, 좌표, 선거, 유형이다.
- 그 아래 검증 네 줄과 출처 목록을 둔다.

### 피드와 제보
- 피드 행: 발신 시각, 발신처, 원문 링크, 한 줄. 기록 승격 링크가 있을 때만 증거로 연결한다.
- 제보 목록: 미확인, 장소, 시각만.
- 제보 상세: 들은 내용과 확인하지 않은 항목.
- 제보 본문을 홈에 두지 않는다.

### 통계 `/stats`, `/stats/:id`
- 목록은 분석 제목과 기간만 둔다.
- 분석 페이지는 지도 하나와 질문 하나다.
- 첫 문장에 기간, 모수, 계산, 출처를 넣는다.
- 구역 비교는 색면, 장소 비교는 점이다. 색과 점 크기를 한 지도에 겹치지 않는다.
- 오른쪽은 방법 네 줄과 표다. 사용한 기록 카드는 지도 아래 링크다.
- 시간대 비교는 같은 축척의 작은 지도를 나란히 둔다.
- 찍지 않는 점: 피드, 미확인 제보, 좌표 없는 카드.

### 시각 규칙
- 서체는 하나다.
- 색은 배경, 글자, 구분선, 상태 네 가지면 충분하다.

## 6. 검색과 생성형 인용
- 회수가 먼저다. 빌드 결과 HTML에 제목, 설명, H1, 첫 문단이 있어야 한다. 클라이언트만 그리는 빈 셸로 두지 않는다.
- 경로마다 `title`, 150자 안팎 `description`, `canonical`.
- 홈과 층 목록, 상세를 사이트맵에 넣는다. `lastmod`는 레코드 수정 시각이다. `/admin`은 제외한다.
- `robots.txt`에 사이트맵을 적는다.
- 상세 첫 문단이 인용 단위다. 날짜, 장소, 상태, 출처가 그 문단에 있다.
- JSON-LD와 `llms.txt`는 정리용이다. 인용 증가 수단으로 먼저 하지 않는다.
- 키워드를 제목과 본문에 반복하지 않는다.

## 7. 구현 순서
1. 데이터 타입과 상태 상수. 기존 증거 레코드를 기록으로 매핑.
2. 홈, 기록 목록, 상세를 위 규칙으로 교체. 확대를 막는 뷰포트 메타 제거.
3. 피드, 제보 경로. 공개 필드에서 식별 정보 제외.
4. 통계 한 편. 색면 지도 하나, 방법 네 줄, 사용 카드 링크.
5. 빌드 시 경로별 HTML, 사이트맵, canonical. 그다음 Search Console.
6. Analytics는 방문이 생긴 뒤. 설치가 색인 조건이 아니다.

## 8. 완료 기준
- [ ] 홈 첫 화면에서 네 층의 입구가 보이고, 건수 합산이 없다.
- [ ] 기록 상세를 새로고침해도 첫 문장과 출처가 HTML에 있다.
- [ ] 통계 지도 범례에 모수와 제외 항목이 적혀 있다.
- [ ] 제보 공개면에 이름과 연락처가 없다.
- [ ] 사이트맵에 상세와 분석 주소가 있고 `/admin`은 없다.
