# 0011 상태 두 단계 — 명세

- 의도: `intent/0011-two-statuses.md`
- 0001 명세의 상태 네 가지와 검증 네 줄 필수 규칙을 대체한다.

## 1. 상태
| 값 | 라벨 | 범례 |
|---|---|---|
| `confirmed` | 자료 확인 | 운영진이 사진·영상·문서를 보고, 장소가 투표소·개표소 단위로 특정된 것을 확인했다. 자료의 진위나 위법 여부를 판단한 것은 아니다. |
| `reported` | 제보 | 자료가 없거나 장소가 특정되지 않은 제보다. 운영진이 아직 자료를 확인하지 않았다. |

- 영어 라벨: Material checked, Tip.
- 옛 값 대응: `document`, `video_confirmed` → `confirmed`(운영자가 붙였던 값). `allegation`, 빈 값 → `reported`.

## 2. DB
- 마이그레이션 `supabase/migrations/20261025020000_two_statuses.sql`: 옛 값을 옮기고, 제약을 두 값으로 바꾸고, 기본값 `reported`, `not null`.
- `scripts/supabase_schema.sql`도 같게 고친다.

## 3. 관리 화면
- 상태 선택은 두 가지다.
- `confirmed`로 저장하려면 장소와 매체(사진·영상·문서 1개 이상)가 있어야 한다.
- 검증 네 줄은 선택 입력으로 남긴다. 상세 화면에는 채운 줄만 보인다.

## 4. 화면 문구
- 홈: "수집 N건 · 자료 확인 M건". 영어판: "N collected · M material checked".
- 소개의 상태 설명, 대표 사례의 미확인 안내, llms.txt 범례가 새 정의를 따른다.

## 5. 첫 일괄 적용
- Claude가 공개 증거 가운데 "장소가 투표소·개표소·선관위 등으로 특정 + 매체 있음" 후보 목록을 만든다.
- 운영자가 목록을 승인하면 그 id만 `confirmed`로 바꾼다.
