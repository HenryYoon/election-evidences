# 0005 개인정보 동의와 처리방침 — 명세

- 의도: `intent/0005-privacy-consent.md`
- 이 문서는 `spec/0004-purpose-and-tip-upload.md` 3장의 동의 문구와 보관 규칙을 대체한다.

## 1. 보유 기간
| 항목 | 보유 기간 |
|---|---|
| 이름·연락처 | 검수가 끝나면 즉시 파기. 검수 전이라도 접수 후 90일이 지나면 파기 |
| 접속 IP 변환값 | 접수 후 1일 |
| 기각한 제보의 원문·첨부 파일 | 검수가 끝나면 즉시 파기 |
| 채택한 제보의 원문·첨부 파일 | 그 제보로 만든 기록을 공개하는 동안. 기록을 지우면 파기 |
| 검수하지 않은 제보의 원문·첨부 파일 | 접수 후 1년 |

## 2. 제보 폼 동의
- **필수 동의 1, 개인정보 수집·이용:**
  - 목적: 제보 사실 확인과 검수, 채택한 제보로 기록 작성, 남용 방지
  - 항목: 장소, 시각, 내용, 링크, 첨부 파일(파일 속 촬영 위치·시각 정보 포함), 접속 IP 변환값
  - 보유 기간: 1장 표
  - 거부 권리: 동의를 거부할 수 있다. 거부하면 이 폼으로 제보할 수 없다.
- **필수 동의 2, 국외 이전:**
  - 이전 항목: 위 필수 항목, 적은 경우 이름·연락처
  - 국가와 받는 자: 호주, Supabase(privacy@supabase.com)
  - 시기와 방법: 제보를 보낼 때 암호화된 네트워크로 전송
  - 목적과 기간: 저장·처리 위탁. 기간은 1장 표와 같다
  - 거부 방법과 효과: 체크하지 않으면 된다. 거부하면 이 폼으로 제보할 수 없다
- **선택 동의, 이름·연락처:**
  - 이름이나 연락처를 적은 경우에만 필수로 체크한다
  - 목적: 사실 확인 연락
  - 보유 기간: 1장 표
  - 거부 효과: 이름·연락처 없이도 제보할 수 있다
- 안내: "정치적 견해 등 민감정보와 다른 사람의 개인정보는 적지 마세요."
- 처리방침 링크를 둔다.

## 3. 처리방침 `/privacy`
- 시행령 제31조 항목을 담는다.
  - 처리 목적, 항목, 보유 기간
  - 파기 절차와 방법
  - 제3자 제공: 없음
  - 처리 위탁과 국외 이전
    - Supabase(호주): 제보 저장
    - Vercel(미국): 사이트 전송과 접속 기록
  - 정보주체의 권리와 행사 방법
  - 안전성 확보 조치
  - 자동 수집 장치: 쿠키를 쓰지 않는다. 관리자 로그인 정보만 브라우저 저장소에 둔다
  - 보호책임자
  - 권익침해 구제 기관
  - 시행일
- 모든 공개 페이지 아래에 처리방침 링크를 둔다.
- 사전 렌더링하고 사이트맵에 넣는다.

## 4. 파기
- 기각: `finish_tip_review`가 원문과 이름·연락처를 지운다. 장소, 시각, 링크도 비운다. 첨부 파일은 관리자 화면이 먼저 지운다(0004).
- 매일 한 번 GitHub Actions(`retention.yml`)가 파기한다. 순서는 다음과 같다.
  1. `retention_due_tips()`로 파기할 제보 id를 받는다.
  2. Storage API로 첨부 파일을 지운다.
  3. `apply_retention(ids)`가 해당 제보 행을 지운다. IP 변환값과 90일 지난 이름·연락처도 이 함수가 지운다.
- 두 함수는 service_role만 실행한다. 비밀 키는 GitHub Secrets에만 둔다.

## 5. 완료 기준
- [ ] 동의 세 가지가 나뉘어 있고, 선택 동의는 이름·연락처를 적을 때만 요구한다(단위 테스트, e2e).
- [ ] `/privacy`가 사전 렌더링되고 모든 공개 페이지에서 링크된다.
- [ ] SQL 검사: 기각하면 원문이 지워진다. 1일 지난 IP와 90일 지난 연락처가 지워진다. anon과 authenticated는 파기 함수를 부르지 못한다.
