# 0004 사이트 목적 안내와 제보 파일 업로드 — 명세

- 의도: `intent/0004-purpose-and-tip-upload.md`
- 이 문서는 `spec/0001-evidence-desk.md` 5장 홈의 "상단 한 문장" 예시(날짜·장소 형식)를 바꾼다. 상단 문장은 사이트 목적을 말한다. 건수를 넣지 않는 규칙은 그대로다.

## 1. 홈
- H1 바로 뒤 첫 문단은 목적 문장과 면책 문장이다.
  > 2026 지방선거의 사전투표, 본투표, 개표 과정을 담은 사진·영상·문서를 모아 날짜, 장소, 출처와 검증 상태를 붙여 공개한다. 상태는 조사 분류이며 법적 결론이 아니다.
- 그 아래 세 단계 목록을 둔다: 모은다, 확인한다, 확인한 만큼만 공개한다. 끝에 소개 페이지 링크를 둔다.
- 네 층 카드에 층의 성격을 한 줄씩 적는다. 최신 한 건 표시는 그대로다.
- 검색용 설명(description)은 첫 문단과 같은 내용을 쓴다.

## 2. 소개 `/about`
- 사전 렌더링하고 사이트맵, `llms.txt`에 넣는다.
- 상단 내비게이션 오른쪽에 "소개" 링크를 둔다. 네 층 내비게이션과 구분한다.
- 내용 순서: 목적(첫 문단), 네 층, 상태 네 가지와 뜻(`status.ts` 범례), 검증 네 줄, 하지 않는 것, 정정과 문의.
- 정정 요청은 제보 폼으로 받는다. 기록 주소를 함께 적게 한다.
- 운영자 개인 정보는 적지 않는다(열린 질문).

## 3. 제보 파일 업로드
| 항목 | 규칙 |
|---|---|
| 버킷 | `tip-uploads`, 비공개(public=false) |
| 형식 | JPEG, PNG, WebP, HEIC/HEIF, MP4, MOV, PDF |
| 크기 | 파일당 20MB. 큰 영상은 링크로 받는다 |
| 개수 | 제보 하나에 5개 |
| 경로 | `<제보 id>/<순번>.<확장자>`. 브라우저가 이름을 만든다. 원래 파일 이름은 쓰지 않는다 |
| 올릴 수 있는 때 | 제보를 접수한 뒤 30분 안, 검수 전(`review = 'new'`) |
| 전체 상한 | 버킷 전체 1시간 60개, 누적 500MB. 넘으면 거절한다 |
| 읽기 | 관리자만. anon은 읽기, 목록 조회, 덮어쓰기, 삭제를 못 한다 |
| 검수 | 관리자 화면에 첨부 파일을 서명 주소로 보인다. 기각하면 첨부 파일을 지운다. 채택하면 남겨 두고, 관리자가 비식별화한 뒤 공개 버킷에 올린다 |

- 업로드 순서: 제보 접수(`submit_tip`가 제보 id를 돌려준다) → 파일 업로드. 파일 일부가 실패하면 제보는 접수된 채로 두고, 실패한 파일 수와 링크로 보내는 방법을 안내한다.
- 공개 번들에 Supabase SDK를 넣지 않는다. 업로드는 Storage REST를 `fetch`로 부른다.
- 원본 파일의 위치·시각 정보(EXIF)는 지우지 않는다. 검증에 쓴다. 동의 문구에 이 사실을 적는다.
- 동의 문구에 수집 항목(첨부 파일), 보관(기각 시 삭제), 공개(비식별화 뒤에만)를 더한다.

## 4. 완료 기준
- [ ] 홈 HTML 첫 문단에 목적 문장이 있다.
- [ ] `/about`이 사전 렌더링되고 사이트맵에 있다.
- [ ] anon은 조건을 만족할 때만 `tip-uploads`에 올리고, 읽지 못한다(SQL 검사).
- [ ] 제보 폼에서 파일을 고르고 보낼 수 있다(e2e).
