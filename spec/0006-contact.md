# 0006 문의 페이지 — 명세

- 의도: `intent/0006-contact.md`

## 1. 문의 폼 `/contact`
- 항목: 종류(문의, 건의, 정정 요청, 개인정보 요청), 내용(10~5000자), 회신 이메일(선택).
- 동의 세 가지를 나눠 받는다(0005와 같은 방식).
  - 필수 수집·이용: 목적, 항목(종류, 내용, 접속 IP 변환값), 보유 기간, 거부 권리.
  - 필수 국외 이전: Supabase(호주, 저장), Resend(미국, 메일 발송).
  - 선택 회신 이메일: 회신 이메일을 적은 경우에만 묻는다. 동의하지 않으면 회신 이메일을 보내지 않는다.
- 미끼 칸을 둔다.
- 처리방침 링크를 둔다.

## 2. 저장과 발송
- 브라우저가 `submit_inquiry`를 부른다. 이 RPC는 anon이 실행할 수 있다.
  - 함수는 입력을 검사하고 비율 제한을 건다. IP당 1시간 3건, 전체 1시간 50건이다. IP는 0003처럼 `cf-connecting-ip`를 우선한다.
  - 함수는 `inquiries`에 저장하고 id를 돌려준다.
- 브라우저가 `/api/contact`에 id를 보낸다.
  - 서버 함수는 `claim_inquiry_mail(id)`을 부른다. 이 함수는 접수 10분 안이고 아직 발송하지 않은 문의만 한 번 돌려주고, 발송 표시를 남긴다.
  - 서버 함수는 Resend로 운영자에게 메일을 보낸다. 회신 이메일이 있으면 reply-to로 넣는다.
- 서버 함수에 Supabase service key를 두지 않는다. id는 UUID라서 접수한 사람만 안다.
- 환경변수: `RESEND_API_KEY`, `CONTACT_TO`. 둘 다 `VITE_` 접두사를 붙이지 않는다.
- 메일 발송이 실패해도 문의는 저장돼 있다. 관리자 화면에서 볼 수 있다.

## 3. 보유 기간
| 항목 | 보유 기간 |
|---|---|
| 문의 내용과 회신 이메일 | 접수 후 1년 |
| 접속 IP 변환값 | 접수 후 1일 |
| 운영자 메일함의 사본 | 운영자가 같은 기간 뒤 지운다 |

- `apply_retention`이 문의도 파기한다.

## 4. 연결
- 처리방침 6장(권리 행사), 9장(보호책임자)의 창구를 문의 페이지로 바꾼다. 처리 위탁 표에 Resend를 더한다.
- 소개의 "정정과 문의"를 문의 페이지로 연결한다.
- 공개 페이지 아래 링크에 "문의"를 더한다.
- 관리자 화면에 "문의" 탭을 둔다. 목록을 보고 처리 완료로 표시한다.
